# Intent: CI that follows Turborepo's guidance and fits private client projects

Author: Joe Takara (Developer Productivity). Status: draft.

## Problem

The CI in this repository and in the templates has drifted from Turborepo's official guidance and from what a private client repository can run. The CI steps the AI-native SDLC Playbook describes, such as evals, triage, the `@claude` fix loop, the production gate, and rollback, are plays, and `intent/restore-playbook-plays/intent.md` covers them.

## Proposed outcome

- CI follows Turborepo's official guidance: it finds changed apps with `turbo query affected`, runs checks with `turbo run --affected`, builds images with `turbo prune --docker`, and names no app in code.
- The root CI keeps its checks in separate jobs by kind, as other projects do (`anthropics/anthropic-sdk-typescript`: lint, build, test; `anthropics/claude-code-action`: test, prettier, typecheck; `withastro/astro` and `vitejs/vite` likewise), and drops the Release Integrity job: on the release pull request it repeats format, `package.json` order, build, and publint, which the same run already checks (`.github/workflows/ci.yml`, lines 55–57 and 321–343).
- Scanners:
  - CodeQL runs only in the root, through GitHub's code scanning on this public repository; the templates do not use it, and `templates/base/.github/workflows/codeql.yml` is removed. The templates keep Semgrep (`sast.yml`) for static analysis and OSV-Scanner for dependency vulnerabilities, because both run on a private repository without a license. Dependency Review and Scorecard stay in the root and in the templates. On a private repository both need a paid license: Dependency Review needs GitHub Code Security or GitHub Advanced Security, and Scorecard "Private repositories are supported if they have GitHub Advanced Security" (`ossf/scorecard-action` README). Most client repositories are on a paid plan that has it. In the templates both run when the repository is public or licensed, as `scorecard.yml` already does, and `dependency-review.yml` gets the same condition.
  - Keep both secret scanners: gitleaks runs fast at commit time and in CI, and holds the payment card (PAN) rules in `.gitleaks.toml`, which stay in every template even though no template handles payments, because client projects may, and card numbers can leak through fixtures, logs, or copied test data, a company decision that no playbook page covers; TruffleHog in CI checks whether a found secret is still live.
  - Keep diff-cover for the templates' patch coverage gate: it runs inside CI with no paid service, which private projects need. The root keeps Codecov, which is free for this open-source repository. A Vitest threshold cannot replace either, because it measures the whole project, not the changed lines.
  - Keep Trivy, hadolint, zizmor, Scorecard, and the pull request title check. Some overlap: in the root, zizmor and CodeQL both check workflow files for issues such as code injection, cache poisoning, and broad permissions; in the templates, which run no CodeQL, zizmor is the only workflow check. Scorecard repeats some of those checks and Dependabot's vulnerability alerts, but it scores the repository's security posture as a whole, which no other tool does. zizmor stays in both, so the root and the templates run the same tools.
  - Remove the `changes` label from `.github/labeler.yml`.
- A CI decision that departs from the playbook or from a tool's official documentation records the reason in that change's `spec.md` or `plan.md`, which the playbook commits as the audit trail (pages 7 and 20).
- The root and every template have a rule in `.agents/rules/`, scoped to `.github/**`, that tells an agent how to write a workflow safely, following the Next.js `.github/AGENTS.md`. It is rendered for Claude Code and Cursor like the other scoped rules. Where the Next.js advice conflicts with a workflow here, such as `pr-triage.yml` using `pull_request_target`, the spec decides.

## Affected users and systems

- This repository's `.github/workflows/`.
- Every template's `.github/workflows/`, `.github/scripts/`, Dockerfiles, and `SETUP.md`.

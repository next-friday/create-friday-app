## Proposed outcome

- The shell gate is small, in the root and in every template: it blocks only the bypasses that matter, such as skipping Git hooks and editing protected paths, and its test covers only those cases.
- The rules that load in every session are short, in the root and in every template: overlapping rules are merged, and only rules about this repository's own conventions remain.
- A correction to rules, hooks, or agent settings goes into the pull request where it is found, and code owners approve it there; the separate-issue rule is removed.
- No file names a path, tool, or step that the project does not have: the review instructions name this project's generated paths, the rules name only the tools the project runs, and the contributing guide drops the finished first-publish steps.
- Templates ship only dependencies their code uses.
- The managed settings example is tailored to the template's own commands and hosts.
- The `agent-owned-work` rule is removed everywhere: the rule, its rendered copies, and every entry that names it.
- The `AGENTS.md` note on commit messages is removed.
- The four code rules keep their code guidance and lose the sentences about talking to the person in the session.
- `current-state-authority.md` is removed everywhere: the rule, its rendered copies, and every entry that names it.
- The root's `git-workflow` skill describes the root's own hooks; the templates keep the first-commit exception, which their hooks allow.
- Agent settings keep denying edits to the configuration of every check, such as lint, format, and commit rules, so an agent fixing code cannot weaken the check on that code (page 32, step 7); a person changes them through a pull request that code owners review. The deny list names only files that exist, in the root and in each template.
- The root's CI change filter and Dependabot groups name only paths and dependencies that exist in the root.
- The list of stack files that replace `base` files lives only in `AGENTS.md`; `.cursor/BUGBOT.md` and `CONTRIBUTING.md` link to it.
- `deterministic-testing.md` alone decides when a test is added; the templates' `AGENTS.md` files drop the sentence about asking before component tests.
- Payload's pnpm settings live only in the stacks that use Payload, `payload` and `turborepo`; the base file keeps the settings every stack needs, such as the `katex` override.
- The `git-workflow` skill keeps the merge gate as a rule, not a conversation: the agent never merges a pull request; a person merges it after code owner approval.
- A bug fix keeps the failing-test-first order (page 32, step 4), and its test is protected by review instead of the marker file: `REVIEW.md` rejects a bug-fix pull request that changes an existing test, and `CODEOWNERS` names an owner for the test folders. The marker file, the test-edit gate, and their wiring are removed, in the root and in every template.
- The review instructions live only in `REVIEW.md`, in the root and in `templates/base/`: `.agents/review.md` and the line that copies it are removed, and `.cursor/BUGBOT.md` and `SETUP.md` point to `REVIEW.md`.

## Affected users and systems

- Every engineer and agent session in this repository and in every generated project.
- `.agents/hooks/`, `scripts/`, `package.json` scripts, and `AGENTS.md`, in the root and in `templates/`.

## Constraints

- The agent still cannot weaken the checks on its own work (page 32); CI and code owner review stay the boundary.
- Hooks are constitution files and change as `constitution-changes.md` describes.

# Review phase: review the pull request and drive it to green

1. Find what to review: the pull request this session just opened, or the pull request or branch the request names. When there is no pull request, or this session cannot reach its host, review the branch's diff against the default branch and put the findings in your reply in place of a comment.
2. Review with a fresh context. Start a subagent that has not seen the work, and give it only the diff, `REVIEW.md`, and the change's `intent/<change>/spec.md` and `plan.md`. When you cannot start a subagent, read the diff again from the first line as if someone else wrote it. The review runs each pass in `REVIEW.md` and reports each finding with its pass, **Important** or **Nit**, `path:line`, and the evidence. When the project has no `REVIEW.md`, run three passes: bugs, security, and whether the change matches its spec and plan. A change with no `spec.md` or no `plan.md` is itself a finding.
3. Post the findings as one comment on the pull request, most severe first. Write "No findings" when there are none. A finding does not decide the merge.
4. On a pull request or a branch that this session did not create, skip steps 4 and 5: change nothing and push nothing. Otherwise, fix every Important finding and every Nit that is correct, run the checks under **Verifying your work** in `AGENTS.md`, and push. Answer each finding you do not fix with the reason.
5. Sweep the pull request: read every unresolved review comment and every failing check, fix what each one reports, push, and answer the comment. Repeat until every check passes and no comment is unanswered. Never skip, disable, or weaken a test to pass a check. When a review flags the same mistake a second time, add the correction to `AGENTS.md` under **Things Claude gets wrong** in the same push. When a check fails for a cause outside this change, such as an outage, say which check and why in one comment, and go to step 6.
6. **Gate: a code owner approves the pull request, and a person merges it.** You never approve it and never merge it. Report the pull request's URL, or the branch's name when there is none, and that it waits only on the code owner. When a new comment or a failing check arrives, go back to step 5.

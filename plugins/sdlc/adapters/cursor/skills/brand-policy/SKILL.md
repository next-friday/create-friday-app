# Brand policy

This is the default; the owner adds the brand's names, colours, typefaces, and tone of voice by editing this file.

## Rules

1. A change with no user-visible text, colour, typeface, logo, or message meets this policy; say "Does not apply" and why.
2. The organization's name, product names, colours, typefaces, and logo files each have one declared source in the project. The spec names that source for every brand value the change shows. When the source does not exist yet, creating it is a requirement of the spec.
3. No code, style, email, or message the user sees holds a brand value as a literal; each reads it from that source. Project metadata such as `package.json`, `README.md`, and `LICENSE` is outside this rule.
4. Text the user reads uses one name for one thing and the same words for the same action on every screen.
5. A brand value this file does not give, such as an exact colour or a tone of voice, is an area of concern. Never invent one.

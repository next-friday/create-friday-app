## Proposed outcome

- The shell gate is small, in the root and in every template: it blocks only skipping Git hooks, and its test covers only those cases.
- The rules that load in every session are short, in the root and in every template: overlapping rules are merged, and only rules about this repository's own conventions remain.
- A correction to rules, hooks, or agent settings goes into the pull request where it is found, and code owners approve it there; the separate-issue rule is removed.
- No file names a path, tool, or step that the project does not have: the review instructions name this project's generated paths, the rules name only the tools the project runs, and the contributing guide drops the finished first-publish steps.
- Templates ship only dependencies their code uses: `fast-check` leaves the templates that do not use it, together with its `ignoreDependencies` entries, and the `BUGBOT.md` rule that ships it everywhere is removed. A team adds `fast-check` when its tests need it.
- The managed settings example is tailored to the template's own commands and hosts.
- The `agent-owned-work` rule is removed everywhere: the rule, its rendered copies, and every entry that names it.
- The `AGENTS.md` note on commit messages keeps only what stays true, the 50-character subject limit, and drops the trailer rule.
- The four code rules keep their code guidance and lose the sentences about talking to the person in the session.
- `current-state-authority.md` is removed everywhere: the rule, its rendered copies, and every entry that names it.
- The `git-workflow` and `script-driven-changes` skills are removed everywhere: the skills, their rendered copies, and every entry that names them, in the root and in every template.
- Agent settings keep denying edits to the check configuration they deny today, so an agent fixing code cannot weaken the check on that code (page 32, step 7); a person changes it through a pull request that code owners review. The deny list names only files that exist, in the root and in each template.
- The root's CI change filter and Dependabot groups name only paths and dependencies that exist in the root.
- The list of stack files that replace `base` files lives only in `AGENTS.md`; `.cursor/BUGBOT.md` and `CONTRIBUTING.md` link to it.
- The templates' `AGENTS.md` files drop the sentence about asking before component tests.
- Payload's pnpm settings live only in the stacks that use Payload, `payload` and `turborepo`; the base file keeps the settings every stack needs, such as the `katex` override.
- `AGENTS.md` states the merge gate as a rule, not a conversation: the agent never merges a pull request; a person merges it after code owner approval. It also keeps any convention from `git-workflow` that no hook enforces, such as the branch name format.
- A bug fix keeps the failing-test-first order (page 32, step 4), and its test is protected by review instead of the marker file: `REVIEW.md` flags a bug-fix pull request that changes an existing test, and the code owner rejects it, because Claude Code Review "never approves or blocks the pull request" ([Claude Code: Code Review](https://code.claude.com/docs/en/code-review)). The marker file, the test-edit gate, and their wiring are removed, in the root and in every template.
- The review instructions live only in `REVIEW.md`, in the root and in `templates/base/`: `.agents/review.md` and the line that copies it are removed, and `.cursor/BUGBOT.md` and `SETUP.md` point to `REVIEW.md`.
- `CLAUDE.md` is the only file that imports `AGENTS.md`: `.claude/rules/agents-guide.md` and the script entry that renders it are removed, in the root and in every template.
- The suppression check, which this repository wrote for itself, runs before each push (in `pnpm verify` at the root and `pnpm check` in the templates) and in CI (`pnpm suppressions:check`), not as an edit hook, and lists only the directives of tools the project runs that no configured lint rule already rejects, in the root and in every template.
- `code-comments.md` names the places this project actually keeps intent, without ADRs, in the root and in every template.
- Local enforcement stays small, as Anthropic's and Next.js's repositories keep it (`anthropics/claude-code-action` runs one hook, Prettier after an edit; `anthropics/claude-code` and `vercel/next.js` run none), because each extra block becomes a bug and a bottleneck, as the `/setup-pstack` case shows. Playbook page 27: hooks "should be fast and scoped", and "Heavier checks … belong at the commit or the PR". In the root and in every template:
  - Kept: Claude Code's built-in `permissions.deny` for the check configuration, hooks, agent settings, and rules, which Claude Code also applies to `cat`, `sed`, `tee`, and redirect targets in Bash; Cursor's file-path gate as its counterpart; the block on skipping Git hooks; the production gate in the templates, which deploy (pages 40–41), while the root, which deploys nothing, drops its copy and the wiring in `.claude/settings.json` and `.cursor/hooks.json`; formatting after an edit; and, in the templates, the playbook's `Read(.env*)` (pages 42–43) followed by `Read(!.env.example)`, the carve-out Claude Code documents for a deny list ([Claude Code: Permissions](https://code.claude.com/docs/en/permissions)), so the agent can still document each variable in `.env.example`, as the templates' `AGENTS.md` requires.
  - Not chased locally: other shell routes into protected files, such as `curl -o`, `python -c`, or a skill installer. Code owner review of the diff catches them, which is the boundary `AGENTS.md` already names; CI catches only what its checks cover, such as a stale rendered rule (`pnpm rules:check`) or a new suppression directive (`pnpm suppressions:check`).
  - Never blocked: anything outside the project's own checkout, such as a developer's `~/.cursor/` and `~/.claude/` or another repository, and restoring a protected file to its committed state.
  - Left to Git and the server: pushing to `main`, which the `pre-push` hook and branch protection stop, and force-pushing, which branch protection stops.
  - Git hooks run what well-known repositories run: `pre-commit` scans staged changes with gitleaks and runs lint-staged, `commit-msg` runs commitlint, and `pre-push` only blocks pushing to `main`. The full checks run in CI on the pull request, the place page 27 names for heavier checks. The templates' `pre-merge-commit` hook and the `pnpm rules:check` at commit are removed, and `CONTRIBUTING.md` and `AGENTS.md` describe the hooks that remain.
  - When a gate blocks a command, its message names the path and the reason (page 40, step 4: "A block should explain itself").

## Affected users and systems

- Every engineer and agent session in this repository and in every generated project.
- `.agents/hooks/`, `scripts/`, `package.json` scripts, and `AGENTS.md`, in the root and in `templates/`.

## Constraints

- The agent still cannot weaken the checks on its own work (page 32); CI and code owner review stay the boundary.
- A change to hooks, rules, or agent settings goes through a pull request that code owners approve.
